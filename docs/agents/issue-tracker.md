# Issue tracker workflow

GitHub Issues is the source of truth for defects, standards gaps, performance
work, and release tasks after the repository is published.

Every issue should state the observed behavior, expected behavior, smallest
reproduction, affected backend/toolchain, and relevant RFC section. Never
include credentials or real identity records. An issue becomes agent-ready only
when acceptance criteria and scope are testable; implementation branches should
reference the issue and pull requests should include test evidence.
